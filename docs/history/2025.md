# LRAC 2025 Historical Recipe

The final 2025 source is preserved at
[commit `5ce2200`](https://github.com/cisco-open/lrac_data_generation/commit/5ce220050ed9b24fb09c2aa00cb7a4b7a1974344),
the annotated [`lrac-2025-final`](https://github.com/cisco-open/lrac_data_generation/tree/lrac-2025-final)
tag, its [GitHub Release](https://github.com/cisco-open/lrac_data_generation/releases/tag/lrac-2025-final),
and the [`archive/2025`](https://github.com/cisco-open/lrac_data_generation/tree/archive/2025)
branch. The tag is the canonical historical reference; the branch exists for
convenient browsing.

The archived README instructed users to clone the repository and source the
top-level recipe from the checkout:

```bash
git checkout lrac-2025-final
. ./prepare_espnet_data.sh
```

Sourcing, rather than executing, mattered because the recipe modified shell
state and relied on paths relative to the current working directory. Its output
defaulted to `./data` and its completion markers were files under `data/tmp`.

## Reproducibility Limitations

- `requirements.txt` was mostly unpinned and included dependencies installed
  directly from Git repositories. `environment.yaml` specified Python 3.10,
  PyTorch 2.3.1, and CUDA 11.8, but did not lock the complete environment.
- The recipe cloned
  `https://github.com/cisco/multilingual-speech-testing.git` with a shallow
  sparse checkout but did not pin a commit. Consequently, the exact external
  open-test data revision cannot be recovered from the recipe alone.
- Speech validation membership was selected during preparation rather than
  being frozen in edition metadata.
- The resampling utility preserved every source channel in multichannel RIR
  files. The 2026 mono materialization policy is therefore a deliberate format
  change rather than byte-level parity with those intermediate artifacts.
- `.done` files recorded only that a stage had run, not the configuration,
  input, code, or output digests used by that stage.

The SHA-256 checksum of the sorted `sha256sum` listing for all 25 files below
`datafiles/` at the final commit is:

```text
9c6e08fe2a6dbde95f2e4d57d393d924dc4a82a475f0f5f5bd3b448cee0aa7a6
```

It was calculated from the repository root with:

```bash
find datafiles -type f -print0 \
  | sort -z \
  | xargs -0 sha256sum \
  | sha256sum
```

The Git commit remains the authoritative record for every individual metadata
file. The aggregate checksum detects any change in file contents or relative
paths, but it does not pin the external evaluation repository described above.

The modern pipeline intentionally does not carry the historical shell scripts
or broad scoring/model environment forward. Check out the tag when historical
behavior is required.

For the initial 2026 compatibility build, the formerly floating public
evaluation checkout is pinned to
[`1a1d300`](https://github.com/cisco/multilingual-speech-testing/commit/1a1d300bf2215c49fb562d4d842e42ad617caea9).
That pin documents the modern compatibility input; it does not retroactively
prove which revision an earlier 2025 run happened to fetch.
